### 1. Componente MetricCard Extraído

**Arquivo:** `components/landing/MetricCard.tsx` (69 linhas)

**Motivação:**
O componente `NossaOperacaoSection.tsx` continha lógica de apresentação de métricas que poderia ser reutilizada. A extração segue o princípio DRY (Don't Repeat Yourself) e melhora a manutenibilidade.

**Implementação:**

```typescript
// components/landing/MetricCard.tsx
interface MetricCardProps {
  value: string;
  label: string;
  index?: number;
}

export function MetricCard({ value, label, index = 0 }: MetricCardProps) {
  return (
    <motion.div
      initial={{ opacity: 0, y: 30 }}
      whileInView={{ opacity: 1, y: 0 }}
      viewport={{ once: true, margin: "-50px" }}
      transition={{
        duration: 0.8,
        delay: index * 0.15,
        ease: "easeOut",
      }}
      className="relative"
    >
      {/* Animação de flutuação suave */}
      <motion.div
        animate={{ y: [-4, 4, -4] }}
        transition={{
          duration: 8,
          ease: "easeInOut",
          repeat: Infinity,
        }}
        className="p-6 md:p-8 rounded-2xl backdrop-blur-sm bg-white/5 border border-white/10 shadow-xl shadow-black/10 text-center transition-all duration-500 hover:bg-white/10 hover:border-white/20"
      >
        <p className="text-5xl md:text-6xl lg:text-7xl font-bold bg-gradient-to-br from-white via-white/90 to-accent/80 bg-clip-text text-transparent mb-3">
          {value}
        </p>
        <p className="text-white/60 text-sm md:text-base font-medium tracking-wide">
          {label}
        </p>
      </motion.div>
    </motion.div>
  );
}
```

**Benefícios:**

✅ **Reutilizável:** Pode ser usado em outras seções que necessitem exibir métricas
✅ **Props Tipadas:** Interface clara com TypeScript
✅ **Animações Melhoradas:** Efeito de flutuação suave adicional
✅ **Responsivo:** Classes Tailwind para diferentes breakpoints
✅ **Acessível:** Gradiente visual para hierarquia de informação

## 🎨 Análise de Design System

### Padrão Identificado: Componentes Internos de Seção

A criação do `MetricCard` dentro de `components/landing/` estabelece um padrão interessante:

**Quando criar componente interno:**
- ✅ Usado múltiplas vezes dentro de uma seção
- ✅ Tem responsabilidade clara e isolada
- ✅ Pode potencialmente ser reutilizado em outras seções similares
- ✅ Melhora legibilidade do componente pai

**Quando NÃO criar componente interno:**
- ❌ Usado apenas uma vez (YAGNI - You Aren't Gonna Need It)
- ❌ Lógica muito simples (< 10 linhas)
- ❌ Fortemente acoplado ao componente pai

### Recomendação para Futuro

Se `MetricCard` for reutilizado em outras seções (não landing), considerar mover para:
- `components/` (raiz) se for genérico
- `components/ui/` se fizer parte do design system
