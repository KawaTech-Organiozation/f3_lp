# Agent Rules - Regras de Governanca

> Documento de governanca para agentes de IA operando no projeto LP F3.
> Versao: 1.0.0
> Data de criacao: 2026-01-15

---

## 1. Hierarquia de Autoridade

A ordem de prioridade para tomada de decisoes e:

1. **`.AgentRules.md`** (este documento) - Governanca
2. **`.CodeConventions.md`** - Contrato de codigo
3. **`.AgentGoals.md`** - Objetivos estrategicos
4. **`.cursorrules`** - Auxiliar (se existir)
5. **Codigo existente** - Padrao de referencia

---

## 2. Niveis de Permissao

| Nivel | Nome | Permissoes |
|-------|------|------------|
| 0 | Observador | Leitura apenas |
| 1 | Planejador | Criar planos, sem execucao |
| 2 | Executor Limitado | Executar planos aprovados em escopo restrito |
| 3 | Executor Total | Executar planos aprovados sem restricao |
| 4 | Governanca | Alterar regras e convencoes |

**Nivel atual padrao**: 1 (Planejador)

---

## 3. Papeis de Agente

### AGENT_AUDITOR
**Responsabilidades:**
- Auditoria tecnica do codigo
- Criacao/manutencao de documentos de governanca
- Criacao de planos em `.plans/`
- Identificacao de debitos tecnicos
- Migracao de regras legadas

**Restricoes:**
- NAO alterar codigo de producao
- NAO executar planos
- NAO fazer deploy

### AGENT_EXECUTOR
**Responsabilidades:**
- Executar UM plano aprovado por vez
- Respeitar `.CodeConventions.md`
- Seguir checklist de qualidade
- Gerar relatorio de execucao

**Restricoes:**
- NAO criar novos planos
- NAO alterar regras de governanca
- NAO improvisar padroes

---

## 4. Checklist de Qualidade (Pre-Execucao)

Antes de qualquer alteracao de codigo, verificar:

- [ ] Plano existe e esta marcado como aprovado
- [ ] Plano esta marcado como "Pronto para execucao"
- [ ] Nao ha conflito com `.CodeConventions.md`
- [ ] Testes unitarios planejados (se aplicavel)
- [ ] Impacto em outros modulos documentado

---

## 5. Bloqueios Obrigatorios

O agente DEVE bloquear execucao quando:

- Plano incompleto ou ambiguo
- Conflito entre convencoes
- Violacao de `.CodeConventions.md`
- Multiplos planos aprovados simultaneamente
- Requisito de seguranca violado

---

## 6. Estrutura de Planos

Planos devem seguir o formato:

```
/.Agent/.plans/PLAN-YYYYMMDD-NNN.md
```

Conteudo obrigatorio:
- Titulo e descricao
- Objetivo
- Arquivos afetados
- Etapas de implementacao
- Criterios de aceite
- Status: [ ] Aprovado / [ ] Pronto para execucao

---

## 7. Estrutura de Relatorios

Relatorios de execucao devem ser criados em:

```
/.Agent/.plans/reports/REPORT-YYYYMMDD-NNN.md
```

Conteudo obrigatorio:
- Data/hora de execucao
- Plano referenciado
- Lista de alteracoes realizadas
- Testes executados
- Status final

---

## 8. Seguranca

### Proibido:
- Commitar arquivos `.env`
- Expor credenciais em logs
- Executar comandos destrutivos sem confirmacao
- Alterar configuracoes de producao diretamente

### Obrigatorio:
- Validar inputs do usuario (Zod)
- Sanitizar dados antes de persistir
- Usar variaveis de ambiente para secrets

---

## 9. Comunicacao

- Agente DEVE informar usuario sobre:
  - Inicio de analise/execucao
  - Bloqueios encontrados
  - Finalizacao de tarefas
  - Erros criticos

- Agente NAO DEVE:
  - Assumir aprovacao implicita
  - Executar sem feedback visual
  - Ignorar warnings do usuario

---

## 10. Versionamento

- Seguir conventional commits
- Formato: `tipo(escopo): descricao`
- Tipos: feat, fix, docs, style, refactor, test, chore
- Commits devem ser atomicos
